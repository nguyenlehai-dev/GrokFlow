# Packaging — Reference `manifest.yaml`

Format đầy đủ của `products/<name>/manifest.yaml`. Đây là vùng vendor
chỉnh khi muốn add/remove module khỏi 1 product.

## Anatomy

```yaml
name: <slug>                  # khớp tên thư mục products/<slug>
label: "Human Label"          # hiển thị trong export log
brand: "Brand Name"           # tham khảo, chưa dùng

remote:
  url: "https://github.com/owner/repo.git"
  branch: main                # mặc định main

defaults:
  backend_host_port: 8000     # documentary; .env override
  frontend_host_port: 5173
  postgres_user: <slug>
  postgres_db: <slug>

include:                      # path từ monorepo backend/+frontend/
  backend:
    - app/core
    - app/modules/grok
    - alembic
    - ...
  frontend:
    - src/modules/grok
    - package.json
    - ...

drop:                         # xóa file/dir kể cả khi parent đã include
  backend:
    - app/modules/admin/git_admin
  frontend:
    - src/modules/admin/views/AdminGitPage.tsx

module_registry:              # ghi đè app/core/module_registry.py
  backend:                    # thứ tự = OpenAPI tag order
    - app.modules.auth
    - app.modules.grok.profiles
    - ...
  frontend:                   # documentary; không dùng tự động
    - admin
    - grok

patches:                      # text edits sau khi copy
  - file: backend/app/...
    find: "exact string"
    replace: "new string"
  - file: backend/app/...
    regex_find: 'pattern'     # DOTALL + MULTILINE flags
    regex_replace: 'sub'      # \1, \2 backrefs OK
```

Ngoài ra, files trong `products/<name>/overrides/<path>` được copy SAU
cùng → ghi đè bất kỳ file nào đã có ở staging tree (kể cả từ
`include`).

## Field-by-field

### `name`
Khớp với tên folder. `export_product.py <name>` đọc
`products/<name>/manifest.yaml`.

### `label`
Hiển thị trong log: `== export flowgrok (FlowGrok — Grok image+video gateway) ==`.

### `brand`
Reserved cho FE branding. Hiện chưa được pipeline đọc — đặt cho future.

### `remote.url`
URL HTTPS của repo GitHub khách. PAT được inject vào URL khi push qua
biến môi trường `$GITHUB_PAT` hoặc `--pat` flag.

### `remote.branch`
Mặc định `main`. Đổi nếu khách dùng `master` hoặc nhánh feature.

### `defaults`
Documentary only — không thực sự được pipeline áp dụng. Để khách biết
port mặc định khi sinh `.env`.

### `include.backend` / `include.frontend`
Danh sách path **relative to `<monorepo>/backend/`** (hoặc `frontend/`)
sẽ được copy vào staging. Có thể là file riêng hoặc thư mục.

**Quy tắc**:
- Path = thư mục → copy đệ quy (skip `__pycache__`, `node_modules`,
  `*.pyc`, `dist`, `build`)
- Path = file → copy 1 file
- Path không tồn tại → in cảnh báo `! missing: ...`, tiếp tục

**Best practices**:
- Liệt kê `app/core`, `app/storage`, `app/services`, `app/workers`,
  `app/scripts` cho mọi product (hạ tầng chung)
- Liệt kê chỉ `app/models/<file>.py` cần thiết — đừng `app/models/`
  toàn bộ vì sẽ pull tất cả model files (model FlowJob/GwRequest có thể
  conflict với manifest sau)
- Module nào thuộc shared (`auth`, `admin`, `entitlements`, `landing`)
  → đa số include nguyên bộ, drop sub-feature qua `drop:`
- Module nào product-specific (grok, flow, gateway) → include nếu product
  ship, skip nếu không

### `drop.backend` / `drop.frontend`
Path xóa khỏi staging sau khi `include` chạy. Cần thiết khi `include`
parent dir nhưng muốn loại 1 sub-file.

Ví dụ flowgrok không có module marketplace UI:
```yaml
drop:
  frontend:
    - src/modules/admin/views/AdminModulesPage.tsx
    - src/modules/admin/services/modules.service.ts
```

(Vì `include.frontend` có `src/modules/admin` toàn bộ, cần xóa các view
cụ thể.)

### `module_registry.backend`
Danh sách Python import path. Pipeline sinh lại
`backend/app/core/module_registry.py` hàm `_load_modules()` với chỉ
các module trong list này.

Ví dụ:
```yaml
module_registry:
  backend:
    - app.modules.auth
    - app.modules.auth.api_keys
    - app.modules.grok.profiles
    - app.modules.grok.jobs
    - ...
```

Pipeline sẽ generate:
```python
def _load_modules() -> list[ModuleManifest]:
    """Auto-generated by export_product.py — do not edit by hand."""
    from app.modules.auth import manifest as auth
    from app.modules.auth.api_keys import manifest as api_keys
    from app.modules.grok.profiles import manifest as profiles
    from app.modules.grok.jobs import manifest as jobs
    # ...

    return [
        auth,
        api_keys,
        profiles,
        jobs,
        # ...
    ]
```

Thứ tự trong list = thứ tự OpenAPI tag hiển thị + thứ tự routes mount.
Conflict route → first wins.

### `module_registry.frontend`
Hiện documentary. Frontend `moduleRegistry.ts` được override qua
`overrides/frontend/src/app/moduleRegistry.ts` (file manual).

### `patches`
List of text edits. Mỗi item:

**Literal find/replace**:
```yaml
- file: backend/app/foo.py
  find: "exact text in source"
  replace: "new text"
```

**Regex find/replace**:
```yaml
- file: backend/app/foo.py
  regex_find: 'pattern .*? end'
  regex_replace: 'new \1'
```

**Cờ regex**: pipeline dùng `re.DOTALL | re.MULTILINE`. `.` match
newline. `^` / `$` match start/end của mỗi line.

**Backreference**: `\1`, `\2` trong `regex_replace` tham chiếu group.

**Tips**:
- Patch không match → log `- patch noop: <file>` (cảnh báo, không fail)
- Patch cùng file áp dụng tuần tự — patch 1 có thể tạo input cho patch 2
- YAML literal block `|` dùng để giữ newline, nhưng cẩn thận về indent
- Nếu pattern phức tạp → dùng `overrides/` file thay vì patch

### Overrides
Thư mục `products/<name>/overrides/<staging-path>/<file>` được copy sau
mọi bước → ghi đè bất kỳ thứ gì đã có.

Ví dụ: flowgrok cần custom `app/models/__init__.py` (trimmed). Đặt:
```
products/flowgrok/overrides/backend/app/models/__init__.py
```

Khi export, pipeline copy file này đè lên `staging/backend/app/models/__init__.py`.

**Khi nào dùng patch vs override**:
- Sửa 1-2 dòng → **patch** (rõ ý đồ trong diff)
- Sửa toàn bộ file (>20% nội dung) → **override** (dễ maintain)
- File quá phức tạp để regex an toàn (vd: dashboard router 550 dòng) → **override**

## Command line

```bash
# Đầy đủ pipeline
python products/_scripts/export_product.py <name>

# Dry-run — chỉ assemble, không push
python products/_scripts/export_product.py <name> --no-push
# → ghi ra dist/<name>-<timestamp>/

# Truyền PAT inline (override $GITHUB_PAT)
python products/_scripts/export_product.py <name> --pat ghp_xxx

# Env var
export GITHUB_PAT=ghp_xxx
python products/_scripts/export_product.py <name>
```

## Verify staged tree

```bash
cd dist/<name>-<timestamp>/backend
python -c "
import sys, os, base64
sys.path.insert(0, os.getcwd())
os.environ['DATABASE_URL'] = 'postgresql+asyncpg://x:x@localhost/x'
os.environ['JWT_SECRET'] = 'x'*32
os.environ['ENCRYPTION_KEY'] = base64.urlsafe_b64encode(b'x'*32).decode()
from app.main import app
from app.core.module_registry import get_modules
print(f'{len(app.routes)} routes, {len(get_modules())} modules')
"
```

Expected:
- flowgrok: `132 routes, 17 modules`
- ai-gateway: `127 routes, 14 modules`
- plxeditor-studio: `143 routes, 19 modules`

Nếu mismatch → có thể manifest đã đổi mà chưa cập nhật doc; hoặc 1 module
load fail.

## Thêm product mới

1. Tạo folder + repo GitHub:
   ```bash
   mkdir products/studio-mini
   # Tạo repo private trên GitHub
   ```

2. Copy manifest từ product gần giống nhất:
   ```bash
   cp products/flowgrok/manifest.yaml products/studio-mini/manifest.yaml
   ```

3. Sửa:
   ```yaml
   name: studio-mini
   label: "Studio Mini — ..."
   remote:
     url: "https://github.com/nt7310063-boop/studio-mini.git"
   include: ...   # giảm bớt modules nếu cần
   drop: ...
   module_registry: ...
   patches: ...
   ```

4. Tạo overrides nếu cần:
   ```bash
   mkdir -p products/studio-mini/overrides/backend/app/models
   cp products/flowgrok/overrides/backend/app/models/__init__.py \
      products/studio-mini/overrides/backend/app/models/__init__.py
   # Sửa import list
   ```

5. Copy docker-compose + deploy artifacts:
   ```bash
   cp -r products/flowgrok/{docker-compose.yml,deploy,HANDOFF.md,LICENSE.txt} \
       products/studio-mini/
   ```

6. Sửa `image` tag trong compose:
   ```yaml
   image: studio-mini/backend:${TAG:-latest}    # thay vì flowgrok/backend
   ```

7. Dry-run:
   ```bash
   python products/_scripts/export_product.py studio-mini --no-push
   ```

8. Check `dist/studio-mini-<timestamp>/` tree.

9. Push:
   ```bash
   export GITHUB_PAT=ghp_xxx
   python products/_scripts/export_product.py studio-mini
   ```
